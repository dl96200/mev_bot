# 方案对比与最优方案选择

## 1. 方案维度
- 执行通道：公共 mempool vs 私有通道
- 策略类型：DEX 套利 vs 清算 vs 闪电贷
- 技术架构：单体服务 vs 模块化微服务
- 语言与性能：Rust/Go/Node.js

## 2. 各方案优缺点

### 2.1 公共 mempool 发送
**优点**
- 简单、通用性强。
- 兼容所有 RPC 节点。

**缺点**
- 容易被抢跑与夹子攻击。
- 成交不确定性高。

### 2.2 私有交易通道（Flashbots/MEV-Share）
**优点**
- 避免抢跑/夹子攻击。
- 成功率更高，可控性强。

**缺点**
- 对 relayer 有依赖。
- 需要适配 bundle 接口。

### 2.3 DEX-DEX 套利
**优点**
- 机会多，入门门槛较低。
- 可自动化程度高。

**缺点**
- 竞争激烈，利润压缩。
- 对 latency 要求极高。

### 2.4 清算套利
**优点**
- 收益相对稳定。
- 链上状态明确（健康因子）。

**缺点**
- 清算事件不连续。
- 需要更复杂的风险判断。

### 2.5 闪电贷套利
**优点**
- 无需大额本金。
- 可组合复杂策略（多跳交易）。

**缺点**
- 需要合约开发与更严格的 gas/失败控制。
- 风险集中在单 tx 失败。

### 2.6 架构选择：单体 vs 微服务
| 方案 | 优点 | 缺点 |
|------|------|------|
| 单体 | 实现快、调试简单 | 扩展性差、耦合高 |
| 微服务 | 可扩展、可替换 | 架构复杂、部署成本高 |

## 3. 推荐最优方案

### 3.1 综合考虑
- **执行通道**：首选私有通道（Flashbots/MEV-Share），公共 mempool 作为备份。
- **策略组合**：DEX-DEX 套利 + 闪电贷套利 + 清算策略。三者互补，平衡稳定性与收益。
- **架构**：模块化单体（核心模块解耦，但部署为单服务），在早期降低复杂度，后续可拆分。
- **技术栈**：Go 或 Rust（推荐 Go 便于快速迭代，后续关键路径可用 Rust 优化）。

### 3.2 最优方案结论
- **最优方案**：
  - 以 **私有交易通道 + 多策略组合** 为核心。
  - 使用 **模块化单体架构**，便于快速上线与迭代。
  - 首期重点实现：
    - DEX-DEX 套利
    - 闪电贷套利
    - 风控与模拟模块

### 3.3 风险与对策
- **竞争激烈**：提升策略速度，加入私有交易通道。
- **Gas 成本波动**：动态 Gas 策略 + 成本控制。
- **策略失败**：模拟验证 + 熔断机制。
